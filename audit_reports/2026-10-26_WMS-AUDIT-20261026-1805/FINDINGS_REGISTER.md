## Detailed Findings

### 1. `FND-DASH-001` — `IdempotentCommandFilter.Fingerprint` throws `NotSupportedException` (`500 Internal Server Error`) on endpoints injecting `[FromServices]`
- **Severity:** `P1` (High — breaks mutating commands when `Idempotency-Key` header is supplied by `apiClient.ts`)
- **Affected Screen / Endpoint:**
  - Observed on `SCR-DASH-001` (`/`): `POST /api/reports/operational-dashboard/exceptions/{code}/acknowledge`
  - Also affected any `[IdempotentCommand]` controller action accepting `[FromServices] ErpKhoDbContext`, `IWarehouseAuthorizationService`, `IRequestMetadata`, `IBusinessPartnerService`, `IProductCatalogService`, or `IFormFile`.
- **Preconditions:** Authenticated user clicks `"Tiếp nhận xử lý"` on an operational exception in the Dashboard (`/`), which sends `POST /api/reports/operational-dashboard/exceptions/IR-QA-001/acknowledge` with an automatic `Idempotency-Key` header generated by `frontend/src/services/apiClient.ts`.
- **Reproduction Steps:**
  1. Navigate to `http://localhost:5173/`.
  2. In the `"Cảnh báo ngoại lệ vận hành"` table, click `"Tiếp nhận xử lý"` on row `IR-QA-001`.
- **Expected Result:** `200 OK` with `{ code: "IR-QA-001", status: "Acknowledged" }` and row button transitioning to `"Đã tiếp nhận"`.
- **Observed Result (Pre-Fix):** `500 Internal Server Error` (`System.NotSupportedException: Serialization and deserialization of 'System.Reflection.MethodBase' instances are not supported. Path: $.db.Model...`).
- **Root Cause (`ERP.Api/Infrastructure/IdempotentCommandFilter.cs:280`):**
  - `IdempotentCommandFilter.Fingerprint` iterated over `context.ActionArguments` and only skipped `CancellationToken`. When an action injected `[FromServices] ErpKhoDbContext db` (such as `ReportsController.AcknowledgeOperationalException`), `JsonSerializer.SerializeToElement` attempted to serialize the entire `ErpKhoDbContext` instance.
- **Fix Applied:**
  - Added `IsNonPayloadArgument(object? value)` in `d:\ERP_KHO\ERP.Api\Infrastructure\IdempotentCommandFilter.cs` (lines 252, 276–310) to exclude `CancellationToken`, `DbContext`, `IWarehouseAuthorizationService`, `IRequestMetadata`, `IBusinessPartnerService`, `IProductCatalogService`, `IFormFile`, `IFormCollection`, `Stream`, and service/infrastructure types from `Fingerprint` serialization and `TrackedWarehouses` reflection.
- **Verification Evidence:**
  - Screenshot: `evidence/screenshots/TC-DASH-001-05_07_regression_after.png`
  - Test Case: `TC-DASH-001-05` -> `PASS_VERIFIED`

### 2. `FND-DASH-002` — Stale `ERP.Api.exe` runtime process (`2026-10-22` Debug build) caused `500` on `POST /api/sales-orders/marketplace-shops/sync-inventory`
- **Severity:** `P1` (High — broke multi-channel marketplace inventory sync on Dashboard)
- **Affected Screen / Endpoint:** `SCR-DASH-001` (`/`), `POST /api/sales-orders/marketplace-shops/sync-inventory`
- **Preconditions:** Running `ERP.Api.exe` process launched from `ERP.Api\bin\Debug\net10.0\` had not been updated with recent source changes because `ERP.Api.exe` locked its own `.dll`/`.pdb` files during `dotnet build`.
- **Reproduction Steps:**
  1. Navigate to `http://localhost:5173/`.
  2. Click `"Đồng Bộ Tồn Kho Đa Sàn Tức Thì"`.
- **Expected Result:** `200 OK` with `syncBatchId` (`SYNC-MKT-*`) and `6` shops synchronized.
- **Observed Result (Pre-Fix):** `500 Internal Server Error` (`Không thể đồng bộ tồn kho đa sàn tức thì.`).
- **Root Cause:** The background watchdog process was running a stale `2026-10-22` binary in `ERP.Api\bin\Debug\net10.0\`.
- **Fix Applied:**
  - Built `ERP.Api` in `Release` (`0 Warnings, 0 Errors`), copied the freshly compiled `2026-10-26` binaries into `ERP.Api\bin\Debug\net10.0\`, and restarted `ERP.Api.exe` via the watchdog on `http://localhost:5260`.
- **Verification Evidence:**
  - Screenshot: `evidence/screenshots/TC-DASH-001-05_07_regression_after.png`
  - Test Case: `TC-DASH-001-07` -> `PASS_VERIFIED`

- **Affected Screen / Endpoint:** `SCR-DASH-001` (`/`), `GET /api/reports/operational-dashboard`

  1. Navigate to `http://localhost:5173/` and inspect `"Nhật ký hoạt động gần đây"`.

  2. `PutToWallSortation` was mapped toInbound category instead of Outbound and lacked a Vietnamese label in `ReportsController.cs` and `Dashboard.tsx`.
- **Fix Applied:**
  - Updated `d:\ERP_KHO\ERP.Api\Controllers\ReportsController.cs` (lines 213, 311, 337) to require `match.Value.Any(char.IsDigit)` in `ExtractAuditReferenceCode` and map `"PutToWallSortation"` to `"Chia chọn đơn hàng theo ô tường"` under `"Xuất kho & điều phối"`.
  - Updated `d:\ERP_KHO\frontend\src\pages\Dashboard.tsx` (line 289) to map `PutToWallSortation: 'Chia chọn đơn hàng theo ô tường'`.
- **Verification Evidence:**
