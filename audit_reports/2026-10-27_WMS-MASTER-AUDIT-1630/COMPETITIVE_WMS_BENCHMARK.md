## 2. Benchmark Scoring Legend

### 2.1 Vendor Capability Scoring Scale (`Oracle_WMS` .. `Manhattan_Active`)
- **`NATIVE_ADVANCED`**: Deep, best-in-class native capability out of the box with advanced algorithmic optimization, real-time orchestration, or enterprise governance.
- **`NATIVE_STANDARD`**: Fully supported out of the box in standard product workflows and documented for production use.
- **`BASIC_OR_ADDON`**: Supported only at a basic level in core or requires an official paid module/add-on (e.g., SuiteApp, AppSource module, external connector).
- **`PARTNER_OR_CUSTOM`**: Requires third-party ISV partner software, custom middleware, or custom code extension.
- **`NOT_SUPPORTED`**: Out of scope or not supported by the platform architecture.
- **`UNVERIFIED_EXTERNAL`**: Public vendor documentation does not provide sufficient detail to verify without proprietary access.

### 2.2 `ERP_KHO` Internal Triangulation & Competitive Position Scale
- **`ERP_KHO_Doc_Status`**:
  - `DOCUMENTED_PHASE1`: Specified as Phase 1 core requirement in Notion/local specs.
  - `DOCUMENTED_PHASE2_3`: Documented in architecture/specs with advanced depth deferred to Phase 2/3.
  - `FROZEN_FUTURE_OD14`: Explicitly frozen for future enterprise tier per Open Decision `OD-14`.
- **`ERP_KHO_Code_Status`**:
  - `IMPLEMENTED_END_TO_END`: Domain + Application + Infrastructure + API + React UI + Automated Tests verified in repo.
  - `IMPLEMENTED_CORE_WITH_PHASE2_DEPTH`: Core Phase 1 flow & API/DB transactions implemented; advanced multi-step/external depth deferred.
  - `IMPLEMENTED_SANDBOX_ADAPTER`: Deterministic internal rule/webhook/adapter engine implemented; live external partner OAuth/API credentials pending Phase 2.
  - `READINESS_STUB_OR_FROZEN`: Governance/telemetry readiness endpoint present; physical hardware/WES integration frozen per `OD-14`.
- **`ERP_KHO_Position`**:
  - `COMPETITIVE_ADVANTAGE`: `ERP_KHO` outperforms global ERP/WMS peers in Vietnam/SEA omnichannel, 3PL, hardware-free scanning, or ledger concurrency invariants.
  - `MARKET_PARITY`: `ERP_KHO` matches mid-market/enterprise WMS production standards (`Oracle`, `D365`, `NetSuite`, `Odoo 19`, `Logiwa`).
  - `MVP_SUFFICIENT`: Meets Phase 1 production operational requirements for initial B2B/3PL rollout, with deeper optimization scheduled for Phase 2/3.
  - `COMPETITIVE_DEFICIT`: Material capability gap compared to Tier-1 or specialized 3PL WMS leaders that must be addressed on the roadmap to win larger accounts.
- **`Gap_Type`**:
  - `NONE_PARITY_OR_ADVANTAGE` · `GAP-TYPE-1 (CODE_VS_DOC_PHASE1)` · `GAP-TYPE-2 (PHASE_2_3_DEFERRED_DEPTH)` · `GAP-TYPE-3 (EXTERNAL_ECOSYSTEM_CONNECTOR)` · `GAP-TYPE-4 (TIER1_ENTERPRISE_AUTOMATION_OD14)`
